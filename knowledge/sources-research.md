# Источники и границы проверки

Этот файл описывает, где проверять получение, рецепты и вероятности и какие ограничения есть у автоматизации. Перед рекомендацией сохраняйте ссылку, статус и дату проверки источника; старые выдержки нельзя выдавать за свежую сверку.

## Где проверять получение, рецепты и вероятности

- **Официальная Warframe Wiki**: [wiki.warframe.com](https://wiki.warframe.com/) и [русская версия](https://ru.wiki.warframe.com/). DE подтверждает официальный хостинг вики совместно с Weird Gloop, включая русскую версию. [Объявление DE](https://forums.warframe.com/topic/1439599-wiki-updates-bug-reporting-discord/). Это официальный адрес общественной вики, а не гарантия безошибочности каждой статьи.
- **Способы получения**: [Warframes Comparison/Acquisition](https://wiki.warframe.com/w/Warframes_Comparison/Acquisition) даёт обзор, а статья конкретного варфрейма — разделы Acquisition и Manufacturing Requirements для источников чертежей и рецепта. Структура источников и вероятностей подтверждается доступной выдержкой [статьи Ivara](https://wiki.warframe.com/w/Ivara). Сверяйте нужную версию предмета, а не переносите рецепт или длительность с другой.
- **Вероятности наград**: [официальные Drop Tables DE](https://www.warframe.com/droptables). По [пояснению DE](https://forums.warframe.com/topic/809777-warframe-drop-rates-data/) таблицы генерируются из внутренних данных PC, могут быть неполными и публикуются с обновлениями, не обязательно с каждым хотфиксом. Храните источник и дату проверки рядом с шансом. Если таблица недоступна, не выдавайте старую поисковую выдержку за свежую сверку.
- **Рецепты и общие правила сборки** дополнительно сверяйте с актуальными руководствами DE и самой Кузницей. [Руководство DE по Excalibur](https://www.warframe.com/en/news/exalibur) показывает основной и компонентные чертежи и отсылает к официальной таблице шансов — это пример структуры, а не универсальный маршрут для остальных фреймов. [Официальная страница Prime Access](https://www.warframe.com/en/prime-access) описывает общий путь Prime: реликвии, Разрывы Бездны, чертежи и сборку.
- **Открытый каталог** [WFCD/warframe-items](https://github.com/WFCD/warframe-items) — сторонний справочник игровых данных; он удобен для идентификаторов, названий и финальной сборки, но не заменяет проверку актуальных способов получения. Его лицензия MIT сохраняется в `knowledge/WFCD-LICENSE.txt`.

## Профиль, mastery и реальное наличие

- **Освоение и владение — разные факты.** AlecaFrame прямо определяет Mastered как достижение максимального ранга даже у уже отсутствующего предмета, а Owned — как текущее наличие в инвентаре. [Foundry: Labels and Indicators](https://docs.alecaframe.com/features/foundry#labels-and-indicators).
- Следствие для базы: снимок публичного профиля или список mastery можно использовать как свидетельство освоения; из него нельзя выводить наличие готового фрейма, дубликатов, его чертежей, компонентов или ресурсов. Это правило учёта, вытекающее из различия состояний, а не проверка конкретного внешнего API DE. `mastered`, `owned`, части и количества должны храниться отдельно; неизвестное наличие не превращается в `false`.
- Полнота публичного профильного endpoint DE не установлена; рабочий доступ к профилю игрока и его данным не проверялся. Наличие открытого профиля само по себе не считается разрешением или технической возможностью скачать весь инвентарь.

## AlecaFrame: документированный API и локальный кэш

### Что описано в документации

- [Страница API](https://docs.alecaframe.com/api) описывает Stats API для собственных сделок и статистики аккаунта, ручной экспорт этих данных и **Relic inventory API**, возвращающий список имеющихся реликвий. [Swagger](https://stats.alecaframe.com/api/swagger/index.html) указан самой документацией.
- Для реликвий нужен публичный токен с доступом `relic`; его создаёт сам игрок в Stats → Create Public Link. Область раскрытия выбирается при создании, токен действует до года и отзывается раньше. `userHash` документация просит не передавать другим. [API: авторизация и параметры](https://docs.alecaframe.com/api).
- **Подтверждённая граница:** на просмотренной странице API описаны статистика и реликвии; документированный экспорт или API всего набора варфреймов, их компонентов и полного инвентаря не подтверждён. Это не доказательство отсутствия другой возможности — перед импортом нужен конкретный образец файла или схема endpoint.
- Возможности интерфейса шире подтверждённого API: [Foundry](https://docs.alecaframe.com/features/foundry) различает owned/mastered и показывает рецепты; [Inventory](https://docs.alecaframe.com/features/inventory) заявлен для предметов, продаваемых на Warframe.Market, поэтому название вкладки само по себе не доказывает полноту экспорта. По [FAQ G6](https://docs.alecaframe.com/faq#g6-when-is-my-inventory-data-updated-how-can-i-force-it) данные обновляются при входе и загрузочных экранах — импорт должен сохранять время снимка.

### Что делается с локальным кэшем

- Публичный [парсер Sainan](https://github.com/Sainan/alecaframe-inventory-parser/blob/senpai/script.pluto) описывает формат `lastData.dat`: AES-128-CBC/PKCS7 и прямой JSON либо обёртка `InventoryJson`. Формат независимо реализован стандартными средствами Node.js в `scripts/lib/alecaframe-cache.mjs` и проверяется тестами на изолированных фикстурах.
- Это чтение готового кэша: доступ к памяти игры, игровому API или файлам авторизации не нужен. Сетевые запросы и вход в аккаунт для импорта не выполняются, кэш никуда не отправляется.
- Санитайзер сохраняет только разрешённый набор полей коллекции: игровые идентификаторы, количества, опыт, ранги, модульные части, Кузницу, кредиты и эндо. Токены, идентификаторы аккаунта и экземпляров, почта, настройки, пользовательские названия и загрузки снаряжения исключаются.
- Статические имена берутся из локального каталога AlecaFrame (`cachedData/json`). Это отдельный снимок стороннего справочника, он не доказывает актуальность рецептов и маршрутов. Нераспознанные позиции остаются по игровому ID и перечисляются в отчёте.
- Полнота остальных игровых подсистем импортом не утверждается: косметика, квесты, Railjack, поглощения Гельминтом и параметры ривенов не импортируются. Правила, команды и проверка повторного импорта описаны в `knowledge/tracking.md`.

## Ограничения проверки

- Некоторые страницы вики блокируются для инструментов чтения через `robots.txt`; в таких случаях используются доступные поисковые выдержки, которые могут быть старше текущей страницы.
- Полную официальную таблицу выпадения бывает трудно прочитать инструментом из-за объёма; подтверждаются её официальный адрес и ограничения DE, а не каждая строка.
- Swagger может открываться как клиентский интерфейс без читаемой схемы в текстовом инструменте: endpoint и формат на практике могут быть не проверены.
- Проверка источников не устанавливает сторонние программы, не создаёт токенов и не подключает аккаунты. Утверждений о гарантированной безопасности стороннего ПО этот файл не делает.
- Сторонние инструменты и интеграции (AlecaFrame, MCP-сервер, открытый каталог) имеют собственные лицензии, ограничения и риски. Опциональная MCP-интеграция описана в `optional/mcp/README.md`.
- Если сведения противоречивы или устарели, честно укажите это в рекомендации и запросите уточнение, а не подставляйте наиболее удобный источник.
