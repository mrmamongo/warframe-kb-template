# Опциональная интеграция warframe-mcp

`optional/mcp/` — необязательная обёртка вокруг стороннего MCP-сервера
[`mpeciakk/warframe-mcp`](https://github.com/mpeciakk/warframe-mcp). Он даёт
ИИ-агенту инструменты **только для чтения публичных данных**: цены Warframe
Market, способы получения, вероятности выпадения, worldstate и т. п.

Интеграция не входит в шаблон, не устанавливается и не запускается
автоматически. Без явной просьбы игрока её не устанавливайте. Требуется
Node.js >= 20, `git`, `npm` и доступ в сеть.

> Дисклеймер: `warframe-mcp` — сторонний код. Шаблон не гарантирует его
> корректность, безопасность и актуальность данных; проверяйте лицензию и
> обновления upstream. MCP-клиент и сам сервер могут обращаться к внешним API.

## Установка

Из корня шаблона (папка `integrations/warframe-mcp/` уже исключена в
`.gitignore`, локальная копия в репозиторий не попадёт):

```powershell
git clone https://github.com/mpeciakk/warframe-mcp.git integrations/warframe-mcp
cd integrations/warframe-mcp
npm ci
npm run build
```

Если `dist/index.js` отсутствует или сборка не удалась, оба скрипта ниже
напишут об этом понятную ошибку.

## Патч (по желанию)

`optional/mcp/warframe-mcp-local.patch` исправляет отображение шансов
выпадения: API отдаёт значения уже в процентах, а upstream местами домножал
их на 100 и печатал завышенные числа. Патч опционален и не меняет поведение
шаблона.

Применение из корня шаблона:

```powershell
git -C integrations/warframe-mcp apply (Resolve-Path optional/mcp/warframe-mcp-local.patch)
```

После применения пересоберите интеграцию:

```powershell
cd integrations/warframe-mcp
npm run build
```

Откат патча:

```powershell
git -C integrations/warframe-mcp apply -R (Resolve-Path optional/mcp/warframe-mcp-local.patch)
```

## Подключение MCP-клиента

Проверенный путь — stdio через лаунчер `optional/mcp/run-warframe-mcp.mjs`.
Лаунчер подставляет нейтральный `User-Agent` и таймаут для
`api.warframe.market`, не редактируя исходники upstream. Пример конфигурации
MCP-клиента (замените путь на свой абсолютный путь к шаблону):

```json
{
  "mcpServers": {
    "warframe": {
      "command": "node",
      "args": ["C:/path/to/warframe-kb-template/optional/mcp/run-warframe-mcp.mjs"]
    }
  }
}
```

Вместо лаунчера можно указать напрямую
`node integrations/warframe-mcp/dist/index.js`, но тогда не будет
нейтрального `User-Agent` и таймаута.

## Проверка

```powershell
node optional/mcp/check-warframe-mcp.mjs
```

Скрипт поднимает сервер по stdio, проверяет рукопожатие и список
инструментов, а если установленная версия отдаёт `lookup_warframe` — делает
один тестовый вызов. Количество инструментов и точные проценты не
захардкожены, поэтому проверка переживает обновления upstream.

Настройки проверки:

- отчёт пишется в `data/imports/<ISO>-warframe-mcp-smoke.json`
  (каталог исключён в `.gitignore`);
- код возврата `0` — проверка прошла, `1` — ошибка (нет сборки, не удалось
  рукопожатие, пустой список инструментов, неуспешный вызов);
- проверка использует сеть: при недоступном API она может завершиться
  ошибкой, и это не означает поломку базы знаний.

## Ограничения

- Инструменты интеграции предназначены только для чтения публичных данных.
  Не передавайте через них личные данные, токены и содержимое локальной базы.
- Шаблон не добавляет MCP-сервер в свою конфигурацию и не запускает его
  в тестах — `npm test` работает офлайн и без этой интеграции.
- Список и поведение инструментов принадлежат upstream; шаблон их не
  фиксирует и не документирует. Актуальную информацию смотрите в README
  upstream-проекта.
